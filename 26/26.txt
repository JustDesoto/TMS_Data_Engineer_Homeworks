Задание 3. Архитектурное решение — мультимодельность?
Может ли быть полезным использование нескольких типов БД в одном проекте?
Ответьте на вопросы:
- Какие модели можно комбинировать?
- Какие преимущества даёт такой подход?
- Есть ли недостатки (например, сложность синхронизации)?

Ответ: Да, использование нескольких типов БД полезно)
  Например, мы можем комбинровать Реляционные + Ключ-значение (в одной мы храним данные о профиле пользователя, во второй - сессии), или же документоориентированная + графовая (в одной - данные по различным документам, во второй - связи между этими документами)
  Преимущества: использование нужного инструмента для необходимой задачи. По примеру с документами и связями между ними: довольно трудно будет делать сотни JOIN запросов в реляционной базе, а в графовой это реализуется очень быстро
  Недостатки: Можно выделить часть из преимуществ, мы применяем несколько технологий, разработчикам необходимо знать несколько языков запросов, возрастает порог входа для новых разработчиков. Для DevOps - это необходимость поддержки сразу нескольких разных типов БД, вместо одной. Применение общих механизмов транзакций (например SAGA паттерн), т.к. мы взаимодействуем сразу с несколькими БД



Задание 4. Выберите конкретные СУБД
На основе ваших решений, предложите конкретные СУБД для каждого модуля и обоснуйте:

Профили пользователей: PostgreSQL (Классическая БД для нормализованного хранения данных, поддержка ACID)
Прогресс обучения: PostgreSQL (Также данные о прогрессе обучения довольно отлично ложатся на PostgreSQL. Строится довольно простая связь Студент-Курс-Урок или т.п.)
Поиск по курсам: ElasticSearch (БД специально для поисковых запросов. Создает свои инвертированные индексы)
Рекомендации: Neo4j (Графовая БД, отлично можем с помощью построения связей формировать списки рекомендаций для пользователей. Например, пользователь А купил курс К, а пользователь Б тоже его купил. Тогда пользователю Б мы можем порекомендовать курс К2, который уже куплен у пользователя А)
Кэширование: Redis (мгновеный доступ к памяти, стандарт для кэшей, различных сессий)
Аналитика: ClickHouse (Колоночная БД, позволяет быстро анализировать данные по необходимым столбцам, т.к. ClickHouse считает не всю строку, а только нужные столбцы)
